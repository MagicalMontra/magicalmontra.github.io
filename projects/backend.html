Independent engineering project

Multiplayer Backend

An ASP.NET Core backend project used to deepen my production-oriented backend skills beyond real-time game-server code.

What it demonstrates

The project focuses on practical backend concerns rather than a minimal CRUD API: persistence, authentication, shared queue state, infrastructure health and integration tests against real services.

Client │ ▼ ASP.NET Core API │ ├── Authentication / JWT │ ├── Application services │ ├── EF Core ─────────────► PostgreSQL │ └── Redis client ────────► Redis │ └── Lua queue operations

Redis-backed login queue

Queue state is stored in Redis instead of process memory so it can be shared by more than one backend instance. Lua is used for multi-step queue operations that need to execute atomically inside Redis.

Persistence and authentication

PostgreSQL and Entity Framework Core provide relational persistence. JWT authentication keeps API identity handling explicit and gives the project a realistic request/authentication path to test.

Integration testing

Testcontainers is used so integration tests exercise real infrastructure in disposable containers rather than relying entirely on mocked persistence. This makes failures around configuration, serialization and database behavior visible.

Current portfolio goal: demonstrate that my C# experience extends beyond Unity application code into ordinary backend architecture, persistence, authentication and infrastructure.
